# Section 02 — Rollout, Token Alignment, and Data Flow for Negative-History OPD

## 1. Purpose of this section

This section defines the data contract for a **pure-OPD/JSD** version of the negative-history method. The goal is not to introduce a new loss yet, but to guarantee that every visual signal, trajectory statistic, and reconstructed target is aligned to the **same student-generated response token**.

The central distinction is:

- **Vocabulary-level visual preference** `u_t(v)` is used to reconstruct a teacher target distribution `q_t(v)`.
- **Realized-token visual conflict** `u_t(y_t)` is gathered only at the token actually generated by the student and is used to describe the history/future state of the sampled trajectory.

The method therefore keeps two parallel information streams derived from the same real/null teacher forwards.

---

## 2. Student rollout

Given the original full image `I` and question `x`, the student generates its own response:

\[
y=(y_1,y_2,\ldots,y_T).
\]

For example:

```text
Question: What pattern is on the shirt?
Student response: The pattern is diamond .
```

For a simplified tokenizer:

\[
y_1=\texttt{The},\quad
 y_2=\texttt{pattern},\quad
 y_3=\texttt{is},\quad
 y_4=\texttt{diamond},\quad
 y_5=\texttt{.}
\]

Store:

```text
response_ids = [y_1, y_2, ..., y_T]
```

At token position `t`, the shared autoregressive prefix is

\[
h_t=(x,y_{<t}).
\]

Thus, for the example:

- `t=1`: prefix = question only.
- `t=2`: prefix = question + `The`.
- `t=3`: prefix = question + `The pattern`.
- `t=4`: prefix = question + `The pattern is`.
- `t=5`: prefix = question + `The pattern is diamond`.

The teacher and student distributions for position `t` must all correspond to this same response-relative state `h_t`.

---

## 3. Three distributions at every response position

For each valid response position `t`, compute three next-token distributions.

### 3.1 Student distribution

The student uses the original full image:

\[
p_t^S(v)=p_\theta(v\mid I,h_t).
\]

This distribution is used in the OPD/JSD training loss.

### 3.2 Privileged teacher distribution

The frozen teacher uses the privileged visual evidence `I^+`:

\[
p_t^+(v)=p_\phi(v\mid I^+,h_t).
\]

### 3.3 Visual-null teacher distribution

The same frozen teacher uses the matched visual-null input `I^0`:

\[
p_t^0(v)=p_\phi(v\mid I^0,h_t).
\]

The teacher parameters, textual prompt, student prefix, and token position are identical between `p_t^+` and `p_t^0`. Only the visual evidence changes.

---

## 4. Example at one token position

Suppose the student has reached

```text
The pattern is
```

and actually generates

\[
y_4=\texttt{diamond}.
\]

For illustration, consider only four groups of next-token probability mass:

| token `v` | student `p_4^S(v)` | privileged teacher `p_4^+(v)` | null teacher `p_4^0(v)` |
|---|---:|---:|---:|
| `diamond` | 0.55 | 0.40 | 0.65 |
| `striped` | 0.15 | 0.35 | 0.10 |
| `wait` | 0.05 | 0.08 | 0.04 |
| other | 0.25 | 0.17 | 0.21 |

These values are only a worked example.

---

## 5. Vocabulary-level visual preference

For every token represented in the chosen distribution support, compute

\[
u_t(v)=\log p_t^+(v)-\log p_t^0(v)
=\log\frac{p_t^+(v)}{p_t^0(v)}.
\]

For the example:

### `diamond`

\[
u_4(\texttt{diamond})
=\log\frac{0.40}{0.65}
\approx -0.486.
\]

The visual evidence suppresses `diamond` relative to the null condition.

### `striped`

\[
u_4(\texttt{striped})
=\log\frac{0.35}{0.10}
\approx 1.253.
\]

The visual evidence increases support for `striped`.

### `wait`

\[
u_4(\texttt{wait})
=\log\frac{0.08}{0.04}
\approx 0.693.
\]

The resulting `u_t(v)` is a vocabulary-level vector.

Its role is to modify the **target distribution**. In the negative-only version, one possible reconstruction is

\[
q_t(v)\propto p_t^+(v)
\exp\left(-\beta_t[-u_t(v)]_+\right),
\]

where

\[
[x]_+=\max(x,0).
\]

The key point in this section is not to finalize this formula, but to preserve the full token-space signal needed to construct `q_t`.

---

## 6. Realized-token visual conflict

The history/future branch uses only the token the student actually generated.

Gather

\[
u_t(y_t)
\]

from the vocabulary-level vector.

For the example,

\[
y_4=\texttt{diamond},
\]

so

\[
u_4(y_4)=u_4(\texttt{diamond})\approx -0.486.
\]

Define realized negative visual conflict

\[
c_t=[-u_t(y_t)]_+.
\]

Therefore

\[
c_4=0.486.
\]

Interpretation:

> The token actually chosen by the student at this position received 0.486 nats of negative real-vs-null visual evidence.

This trajectory statistic is different from the full vocabulary vector used to reconstruct `q_t`.

---

## 7. Example across the complete response

Suppose the gathered visual preferences for the actual generated tokens are

| token | `u_t(y_t)` |
|---|---:|
| `The` | +0.03 |
| `pattern` | +0.05 |
| `is` | 0.00 |
| `diamond` | -0.486 |
| `.` | -0.02 |

Then

\[
c_t=[-u_t(y_t)]_+
\]

gives

| token | `c_t` |
|---|---:|
| `The` | 0 |
| `pattern` | 0 |
| `is` | 0 |
| `diamond` | 0.486 |
| `.` | 0.02 |

A simple cumulative history can be updated as

\[
H_1=0,\qquad
H_{t+1}=H_t+c_t.
\]

Therefore:

\[
H_2=0,
\]

\[
H_3=0,
\]

\[
H_4=0,
\]

\[
H_5=0.486,
\]

and after the final token the cumulative negative evidence is

\[
0.486+0.02=0.506.
\]

This history is computed from the **realized trajectory only**; it is not a vocabulary-wide expectation.

---

## 8. Two parallel tensor branches

The implementation should maintain two logically distinct tensors.

### 8.1 Distribution branch

Typical conceptual shape:

```text
[B, T, V']
```

where

- `B`: rollout batch size,
- `T`: padded response length,
- `V'`: full vocabulary or compressed support such as top-k + tail.

This branch contains

```text
teacher_plus_logprobs
teacher_null_logprobs
student_logprobs
u_vocab
q_target
```

and is used for target reconstruction and JSD.

### 8.2 Trajectory-state branch

Shape:

```text
[B, T]
```

This branch contains values gathered at the realized response token:

```text
u_realized
negative_conflict
history_state
future_state   # if/when used
```

Conceptually:

```python
u_realized = gather(u_vocab, response_ids)
negative_conflict = relu(-u_realized)
```

This branch is used to estimate how much the actual student trajectory has accumulated visual-opposed evidence.

---

## 9. Response-relative token alignment

Do **not** align student and teacher scores by the absolute multimodal sequence index.

The student and teacher visual inputs can produce different numbers of visual tokens:

```text
student input:
[full-image visual tokens x 1200][question tokens][response tokens]

teacher input:
[privileged visual tokens x 300][question tokens][response tokens]
```

Therefore the same response token can occur at different absolute tensor indices.

The invariant coordinate is the response-relative position `t`:

\[
(y_1,y_2,\ldots,y_T).
\]

All saved teacher/student response scores must be cropped/gathered so that response axis index `t` represents the same sampled response token in all conditions.

---

## 10. Causal-LM shift

For an autoregressive model,

\[
p(y_t)
\]

is predicted from

\[
h_t=(x,y_{<t}).
\]

Thus the logit used to score `y_t` is produced before `y_t` itself enters the prefix.

A typical implementation uses a one-token shift, conceptually:

```python
prediction_logits = logits[..., :-1, :]
target_ids = input_ids[..., 1:]
```

The exact offsets depend on the chat template and multimodal processor. Unit tests should verify that the log-probability stored for response token `y_t` is the score predicted from the prefix ending at `y_{t-1}`.

---

## 11. Response mask and variable-length rollouts

Suppose two sampled responses have lengths 5 and 3:

```text
A: The pattern is diamond .
B: Striped pattern . PAD PAD
```

Then

```text
response_mask_A = [1, 1, 1, 1, 1]
response_mask_B = [1, 1, 1, 0, 0]
```

Padding positions must not enter:

- `u_t`,
- realized conflict `c_t`,
- history accumulation,
- future accumulation,
- target reconstruction,
- JSD reduction,
- loss denominator.

The pure-OPD loss should preserve masked averaging, for example

\[
L=
\frac{\sum_{b,t}M_{b,t}\,\ell_{b,t}}
{\sum_{b,t}M_{b,t}}.
\]

---

## 12. EOS versus truncation

Store an explicit `finish_reason`.

At minimum distinguish:

- natural EOS / valid stop,
- maximum-length truncation,
- invalid/infrastructure failure.

This distinction matters for later history/future statistics.

A rollout that reaches `max_new_tokens` while repeating

```text
This is red. This is red. This is red. ...
```

must not be interpreted as if the student deliberately reached a valid terminal state.

This is especially important when future cumulative conflict is later introduced.

---

## 13. Prompt-group identity

If multiple rollouts are sampled for one training example, store a stable

```text
prompt_group_id
```

that identifies the actual multimodal instance, not only its question text.

The identity should include or resolve to the same image/task instance and question.

This field is useful for later variants that compare multiple on-policy trajectories for the same prompt, even though the initial pure-OPD negative-history version does not require a PPO leave-one-out baseline.

---

## 14. Minimal data contract for the pure-OPD version

### Rollout metadata

```text
prompt_group_id
response_ids        # [B, T]
response_mask       # [B, T]
finish_reason
```

### Frozen-teacher scoring

```text
teacher_plus_logprobs   # [B, T, V']
teacher_null_logprobs   # [B, T, V']
```

### Student update forward

```text
student_logprobs        # [B, T, V']
```

### Derived tensors

```text
u_vocab        = teacher_plus_logprobs - teacher_null_logprobs  # [B,T,V']
u_realized     = gather(u_vocab, response_ids)                   # [B,T]
negative_cost  = relu(-u_realized)                               # [B,T]
history_state  = exclusive_cumsum(negative_cost)                # [B,T]
q_target       = reconstruction(...)                             # [B,T,V']
jsd_loss       = JSD(q_target, student_distribution)             # [B,T]
```

In the pure-OPD formulation, `old_policy_logp` is **not required**, because no PPO new/old policy ratio is used.

## 15. End-to-end data flow for this section

```text
Full image + question
        |
        v
Student on-policy rollout
        |
        v
response_ids / response_mask / finish_reason
        |
        +-----------------------------+
        |                             |
        v                             v
Privileged teacher               Null teacher
same student prefix              same student prefix
        |                             |
        v                             v
   log p_plus                    log p_null
        \                             /
         \                           /
          +-------- u_t(v) ----------+
                   |
          +--------+---------+
          |                  |
          v                  v
Vocabulary branch       Realized-token branch
u_t(v)                  u_t(y_t)
          |                  |
          v                  v
reconstruct q_t         c_t -> history/future state
          \                  /
           \                /
            +-- adaptive reconstruction --+
                         |
                         v
                 JSD(q_t, p_t^S)
```

At this stage the `history/future state` is only an auxiliary statistic. Later sections decide exactly how it should modify reconstruction strength or position weighting.

## 16. Relationship to OPD-Aha

This section is almost fully compatible with the OPD-Aha infrastructure.

OPD-Aha already requires:

- student on-policy rollout,
- shared-prefix teacher scoring,
- privileged and null teacher distributions,
- student distribution,
- valid-response masking,
- compressed vocabulary support such as top-k + tail.

The main addition for the negative-history variant is:

\[
\boxed{
\text{gather the existing visual-preference vector at }}_t
}
\]

followed by trajectory statistics such as

\[
c_t=[-u_t(y_t)]_+,
\]

and

\[
H_{t+1}=H_t+c_t.
\]

Therefore this section should be implemented as an extension to the existing OPD-Aha scorer/data path rather than as a replacement training framework.

---

## 17. Main conclusion

The negative-history OPD method needs to preserve **two views of the same visual-preference signal**:

### Distribution-level view

\[
\boxed{u_t(v)}
\]

asks:

> Which candidate next tokens are supported or opposed by privileged visual evidence?

It is used to reconstruct the OPD target.

### Trajectory-level view

\[
\boxed{u_t(y_t)}
\]

asks:

> How much visual opposition did the student’s actually sampled token receive?

It is used to characterize historical and future conflict along the student's own trajectory.

The two quantities come from the same real/null teacher forward passes but should remain conceptually and programmatically separate.
